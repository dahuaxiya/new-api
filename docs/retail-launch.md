# 中转站首版运行说明

本版使用独立 `SITE_MODE=retail` 进程、数据库、会话密钥和文件目录。首批充值采用兑换码，支付宝不配置。部署模板在 `deploy/retail/`，真实凭据不得写入仓库。正式构建与发布遵守根目录 `AGENTS.md`；模板本身不代表已经部署。

## 不配域名时的入口

可在同一 IP 上使用不同 HTTPS 端口，证书必须包含该 IP 并正常续期。托管站保留原有 Cookie 名，中转站使用 `new_api_retail_refresh` / `new_api_retail_has_session`，避免登录和退出互相覆盖。Cookie 名称不是跨应用安全沙箱，两站仍由同一运营者管理；独立数据库和会话密钥不可省略。

## 首批模型与价格

2026-11-15 核对 [OpenAI 官方价格页](https://developers.openai.com/api/docs/pricing) 的 Standard 档。金额单位为 USD / 百万 token：

| 模型 | 输入 | 输出 | 缓存读取 | 长上下文输入 / 输出 / 缓存 |
| --- | ---: | ---: | ---: | --- |
| gpt-6.1-sol | 2 | 10 | 0.1 | 4 / 15 / 0.2 |
| gpt-6-sol | 2 | 10 | 0.2 | 4 / 15 / 0.4 |
| gpt-6-astra | 10 | 50 | 1 | 20 / 75 / 2 |
| gpt-5.6-sol | 4 | 20 | 0.4 | 8 / 30 / 0.8 |
| gpt-5.6-terra | 2 | 12 | 0.2 | 4 / 18 / 0.4 |

总输入超过 272,000 token 时整笔请求使用长上下文价，缓存不能降低档位。通用缓存写入按输入价的 1.25 倍计；未验收 12 小时缓存保留和 Fast / Flex 等服务档，不将其宣称为已支持。GPT-5.6 Sol 是截至 2026-11-30 的官方促销价，期限后需重新核对，程序不会自动猜测新价。

模型价格使用现有表达式编辑器；销售分组 `retail` 的倍率默认 1，可在分组设置调整。例如 1.2 表示所有基础费用乘 1.2。请求预留时冻结价格与倍率，修改不追溯已结算账单。管理员已有显式定价不被新增默认价覆盖。

渠道只登记已核对定价、协议和供货归属的模型。上游列出模型不证明有余额或调用成功；未验收的聊天别名及图片生成模型不加入首批可售列表。

## 运营入口

- 渠道页：创建/修改上游；“供货总览”检查白名单资格；“中转账务”查看客户账单、上游调用和采购成本，按完整请求 ID 核对。
- 中转账务：三类记录独立翻页。`reserved` 不是收入，未知成本不是 0。超过 24 小时未更新的预留，核实无在途请求且上游未计费后才可填写原因释放；失败时保留审核内容，由服务器核对金额和状态。
- 兑换码页：管理员先在支付设置中自行确认项目现有的收费声明，再生成兑换码。兑换码金额是本站钱包额度，不会替上游账户充值。
- 用户钱包页：兑换后创建余额计费 API Key，使用本站 `/v1` 地址调用。上游无余额、请求失败时核对预留释放和钱包余额。
- 首版采购成本查看和核对已提供；成本登记继续使用 `docs/retail-api.md` 的 root API，未提供利润估算或自动账单导入。

## 单机资源与维护

中转站的 Nginx `server` 块引入 `deploy/retail/nginx-static.conf`，安装路径为 `/etc/nginx/snippets/luobocode-retail-static.conf`。仅 `/static/` 下的公开资源开启 gzip；有预压缩文件时优先使用，否则动态压缩。带内容哈希的资源缓存一年，普通文件继续重新校验；缺失资源返回 404，不能回落为 HTML。首页、发布信息、登录和 API/SSE 保持原策略。修改配置先运行 `nginx -t`，再平滑 reload，不需要重启应用。

容器绑定回环地址，TLS 入口交给 Nginx。模板限制 256 MiB 内存、0.75 CPU，设置 Go 内存目标及 Docker 日志轮转。这些是资源隔离设置，不是容量承诺；上线后以实际 RSS、延迟、在途请求和错误率决定并发数。

日志目录和 SQLite 数据位于独立持久化目录。备份使用 SQLite backup API 生成一致快照，不直接复制正在写入的 DB 主文件。升级保留前一版镜像和前端目录，先排空请求；代码回滚不得用旧数据库覆盖新写入。

供货白名单配置通过只读目录挂载，修改前校验后原子替换 `retail.json`。不要把容器单文件挂载当作可热更新配置。所有发布包保留源码、revision 与 SHA-256；切换前核对现场版本并取得后端、前端发布锁。
