# 托管站与中转站的代码复用

两站维护同一仓库、使用同一前端构建和后端程序，由进程环境变量 `SITE_MODE=hosting|retail` 选择业务。独立站点不意味着复制项目。新增公共功能时先改公共实现，站点差异留在相应业务模块。

## 当前边界

| 范围 | 共用实现 | 独立内容 |
| --- | --- | --- |
| 用户界面 | 布局、按钮、表格、图表、主题、翻译、菜单过滤 | 导航顺序、首页主要操作、业务说明 |
| 身份和权限 | 用户管理、登录鉴权与角色检查 | 用户数据、会话与密钥；尚未实现跨站单点登录 |
| 后台维护 | 系统任务租约、历史记录、HTTP 排空 | 各站登记的任务与数据库记录 |
| 交易 | 原有付款交互与公共支付工具 | 托管套餐订单和零售钱包充值、结算账目 |
| 模型接入 | 通用接口和渠道基础能力 | 客户托管绑定与平台销售供货；二者不能混用 |

`web/src/lib/site-profile.ts` 统一定义用户导航、首页操作、说明和额度展示策略。`use-sidebar-data.ts` 和 `overview-dashboard.tsx` 使用同一份配置；首页快捷入口也使用 `useSidebarConfig`，同时遵守管理员菜单开关和用户隐藏设置。修改一个业务入口时，不应再分别复制菜单和首页定义。

托管首页先展示托管账号额度，提供账号、套餐和密钥入口；中转首页提供密钥、账单与兑换、模型价格入口，展示钱包和调用用量。两站继续共用个人数据查询、用量图表和最近记录。管理员访问用户首页仍只读取 self 数据。站点状态尚未返回时，不提前请求托管额度。

这些配置仅控制展示，不能代替后端站点校验、鉴权和数据隔离。其他页面的业务差异仍由各自模块处理，本轮没有将支付或计费逻辑重写为通用框架。公共落地页的既有设计也保持独立。

## 单机运行和后续扩容

当前一台机器可以运行两个进程或容器，使用同一版本的程序；反向代理按两个域名分流。可以共用一个 MySQL/PostgreSQL 服务，但必须使用两个数据库，最好分别授权数据库用户。两站使用不同会话密钥、私有配置、持久化目录和日志目录。共享程序不代表共享账号、余额或支付订单。

托管侧增加 vm2api 执行节点，中转侧增加渠道和平台供货，各自登记和验收。增加整站网关副本仍需完成临时 OAuth 状态共享、全局限流、缓存一致性、其余后台循环协调和 WebSocket 排空；目前继续保持单个生产主节点。中转的 Redis/批量余额写回组合尚不支持，不能因共用基础设施而直接启用。

本轮只修改前端展示配置并提供本地预览，不修改数据库、计费规则或生产部署。生产仍按 `AGENTS.md` 从已推送的 `release` 提交发布到搬瓦工，不使用 CloudCone。
